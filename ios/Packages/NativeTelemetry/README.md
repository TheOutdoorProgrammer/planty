# NativeTelemetry

A bounded native event queue and authenticated HTTPS transport for application-owned telemetry relays.

The package persists only its typed event contract: static operations and outcomes, error classes, originating release/build, random event UUID, timestamps, duration, and optionally an app binary UUID with architecture and text-relative frame offsets. It never stores credentials, endpoints, SQL, user/device identifiers, notification payloads, absolute addresses, diagnostic messages, or raw MetricKit reports. Its queue is excluded from device backups and protected until the first unlock on iOS.

MetricKit supplies OS crash and hang diagnostics. Delivery can be delayed or absent, and requires the OS to deliver a diagnostic while the app can run. This is not an independent crash reporter and does not promise every crash or immediate next-launch delivery. A diagnostic without usable app frames or a recognized architecture still emits a minimal crash/hang failure with its original release/build and no symbol payload. Invalid origin versions remain rejected. The app-only projection preserves `offsetIntoBinaryTextSegment` unchanged and uses the diagnostic's release/build, never the currently installed build. Cross-module frames are dropped.

OpenTelemetry Swift 2.5.0's MetricKit adapter was evaluated. Its diagnostic logger omits each diagnostic's originating application version/build and expands raw exception messages. Using Apple's public `MXMetricManagerSubscriber` directly retains the required origin identity and projects data before custom persistence. The authenticated application relay creates the OpenTelemetry traces/logs. No Grafana credential or general OTLP forwarding capability ships in the client.

The queue holds at most 256 pending events and 16 quarantined events, with a 512 KiB file limit and 30-day expiry. Two reserved slots durably coalesce `telemetry.delivery` failures for capacity and expiry loss, so routine traffic cannot evict the loss report. Capacity evicts routine events before failures and crashes. If failures alone fill capacity, the oldest is replaced and loss remains visible after recovery. Expired loss reports receive a fresh timestamp when delivery resumes. Failed atomic writes leave the previous queue intact. Batches contain at most 16 events from one release/build and cannot exceed 64 KiB. Only HTTP 204 removes accepted events; ambiguous transport failures retain event UUIDs for at-least-once replay. HTTP 400/413/422 quarantine the batch, and other responses retry after at least 60 seconds. Quarantine contains sanitized events only. Repeated delivery is possible after a lost acknowledgment. Concurrent drains are coalesced, requests expire after ten seconds, and redirects are refused.

`NativeTraceContext` binds a newly generated event UUID to the real API request's sampled W3C `traceparent`: the UUID bytes form the trace ID and their last eight bytes form the span ID. Completion persists that same UUID, allowing the relay's eventual parent span to correlate with backend child spans even after offline replay. Existing caller context is preserved; its independent native completion event does not claim a parent relationship.

The event timestamp denotes completion: the relay reconstructs the parent start by subtracting `duration_ms`. API completion is anchored to the request's wall-clock start plus its bounded monotonic duration, using the same duration sent in the event. Exporting the request start as the timestamp would place the entire parent before its backend child.

During a rolling upgrade, a batch containing a valid minimal crash/hang retries HTTP 400 because older relays require frames. Other HTTP 400 responses still quarantine the batch. The queue's 30-day expiry bounds this compatibility retry, and HTTP 204 remains the acknowledgment that removes the diagnostic.

`swift test` exercises privacy projection, originating build retention, bounded persistence, offline replay, rejection, and concurrent drain behavior. App integration must start capture once, supply its existing HTTPS API credential in memory, and drain on foreground/configuration changes. Neither this module nor the application exposes a deliberate crash action.

The `AppleCallStackTree.json` regression fixture comes from Apple's [`MXCallStackTree.jsonRepresentation()` method example](https://developer.apple.com/documentation/metrickit/mxcallstacktree/jsonrepresentation%28%29/). It retains the first complete call stack and its values, closes the partial example, and supplies the missing comma after its root address. This method itself returns the `callStackTree` wrapper; removing it would break Apple's documented API. The test verifies the app frame survives while the system frame and absolute addresses are excluded. Apple's [diagnostic log example](https://developer.apple.com/documentation/appstoreconnectapi/get-v1-diagnosticsignatures-_id_-logs) uses `platformArchitecture: arm64`; the SDK declares the property as a string, so unsupported values omit the symbol payload rather than guessing an architecture.
